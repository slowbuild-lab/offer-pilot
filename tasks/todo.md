# 智联招聘优化任务清单

对应计划：[plan.md](plan.md)。第一阶段已实现并通过测试、构建与本机运行检查；第二、三阶段尚未开始。文件列表是预估，具体路径在实施前核实；每项尽量控制在 3–5 个文件，超出时继续拆分。

## 第一阶段：投递可控

### 任务 1：启动互斥与停止检查

让服务端在异步启动前占用任务，停止后阻止新的投递点击。

- [x] 并发启动请求只创建一个任务，启动失败释放占用。
- [x] 导航、等待和点击前检查取消；停止后不再产生新的投递点击。
- [x] 页面区分启动中、停止中和结束状态，已发出的申请保留结果。

验证：服务层并发测试、隔离页面点击计数、停止发生在确认等待中的回归；运行 `./gradlew --offline --console=plain test --tests '*ZhilianJobServiceTest' --tests '*ZhilianModernLayoutTest'`。

依赖：无。预计文件：`ZhilianController.java`、`ZhilianJobService.java`、`ZhiLian.java`、对应两份测试。

### 任务 2：持久化任务与尝试记录

为每次任务和岗位尝试保存独立记录，作为额度、去重和恢复的依据。

- [x] 增量创建记录表及索引，多次启动迁移幂等，原投递数据完整保留。
- [x] 点击前记预留，点击发出后更新状态；崩溃遗留记录恢复为待核实。
- [x] 数据库查询或写入失败时不继续投递，任务结束原因可读。

验证：临时 SQLite 的迁移、状态转换、故障和重启恢复测试；运行新增记录服务测试。

依赖：任务 1。预计文件：新增智联记录服务、记录模型、`ZhiLian.java`、`ZhilianJobService.java`、记录测试。

### 检查点 A

- [x] 状态与记录测试通过，现有智联回归通过。
- [x] 本地演示启动、停止、数据库失败时的行为，不点击真实投递。

### 任务 3：数量限制配置

在前端设置单次和每日最大尝试次数，提供保存与校验。

- [x] 两个字段可保存、刷新回显；初始建议值 20、50，范围为 1–500 的整数。
- [x] 后端拒绝小数、字符串和越界值，部分更新不覆盖其他配置。
- [x] 页面说明额度针对本工具的尝试次数、每日按北京时间统计、修改后新任务生效。

验证：临时库持久化与 API 参数测试、前端类型检查、浏览器表单核验。

依赖：任务 2。预计文件：新增智联策略配置模型、配置服务、`ZhilianController.java`、`front/app/zhilian/page.tsx`、配置测试。

### 任务 4：点击前执行额度限制

使用持久化尝试记录检查并占用额度，跨任务和重启保持一致。

- [x] 本次限制设为 2 时最多发起 2 次尝试；每日额度不足时按较小剩余额度停止。
- [x] 超时待核实占额度；已确认未点击的预留可释放；跳过岗位不占额度。
- [x] 重启不能清零每日次数，北京时间跨日正确，启用当天说明统计起始时间。

验证：边界 1、2 次、重启、并发占用、23:59 至次日、预留后崩溃；用固定时钟与临时库测试，隔离页面确认无额外点击。

依赖：任务 2、3。预计文件：智联策略服务、记录服务、`ZhiLian.java`、额度测试、浏览器回归测试。

### 任务 5：历史去重与待核实列表

让相同岗位跨关键词、任务和重启保持可追踪，明确区分采集记录与成功记录。

- [x] 同岗位已确认投递或存在待核实记录时不再次点击；仅采集但未投递不被误跳过。
- [x] 老数据库中同岗位多条记录以已确认结果为准，不删除原记录。
- [x] 页面可查看待核实岗位、打开原岗位链接并登记核实结果；不提供自动重投。

验证：重复关键词、数据库重复行、重启后去重、待核实确认成功／未成功的测试。

依赖：任务 2、4。预计文件：记录服务、`ZhiLian.java`、`ZhilianController.java`、待核实前端组件、回归测试。

### 任务 6：异常暂停与人工继续

- [x] 验证码、登录失效、平台限制被识别后没有后续投递点击；识别失败时不能把未知弹窗当成功。
- [x] 连续 3 次实际投递异常触发暂停，确认成功才清零计数。
- [x] 人工继续前重新验证登录与额度；平台当日上限不自动恢复，暂停释放浏览器执行线程。

验证：隔离页面模拟验证码、登录页、额度弹窗、连续失败和成功打断失败计数；验证继续请求互斥。

依赖：任务 1、2、4、5。预计文件：新增智联异常识别器、`ZhiLian.java`、`ZhilianJobService.java`、`ZhilianController.java`、异常测试。

## 第二阶段：投递可解释

### 任务 7：实时进度与等待倒计时

让用户明确知道任务正在处理什么，以及为何结束或暂停。

- [ ] 展示本次已浏览、尝试、确认成功、跳过、待核实数及今日剩余额度。
- [ ] 倒计时随弹窗等待更新；刷新页面后从服务端恢复状态，计数与记录一致。
- [ ] 完成、额度停止、用户停止、暂停、失败具有不同结果提示。

验证：状态 API 测试、隔离任务计数、前端刷新与倒计时核验；不因每秒更新写入数据库。

依赖：任务 1–6。预计文件：状态模型、记录服务、`ZhilianJobService.java`、前端任务状态组件、状态测试。

### 任务 8：确定性筛选规则

增加公司黑名单、排除词和岗位条件筛选，并显示原因。

- [ ] 规则可保存回显，字段有校验，城市／薪资／学历／经验有明确匹配规则。
- [ ] 命中排除规则时不点击投递，并记录跳过原因。
- [ ] 信息缺失或无法解析时进入待确认，不静默放行；规则修改仅作用于新任务。

验证：薪资单位、范围边界、空值、学历经验歧义和排除词匹配的参数化测试；隔离页面确认跳过不消耗额度。

依赖：任务 5、7。预计文件：策略配置模型与服务、筛选器、前端规则组件、筛选测试。

### 检查点 D

- [ ] 实时状态和筛选测试通过，前端构建成功。

- [ ] 重启后提示有可恢复任务，用户未点击继续时不投递。
- [ ] 继续后跳过已确认和待核实岗位，重新校验登录、规则和今日额度。
- [ ] 重复继续请求只启动一个任务；规则变化时要求重新预览或新建任务。

验证：临时库模拟投递前后崩溃、跨日重启、配置变化、重复恢复；隔离页面验证点击次数。

依赖：任务 2、5、6、9。预计文件：记录服务、任务服务、`ZhilianController.java`、前端恢复组件、恢复测试。
